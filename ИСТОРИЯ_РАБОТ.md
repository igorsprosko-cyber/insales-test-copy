# 3. ВАЖНЫЕ УРОКИ

## JS вместо CSS

Category-card инцидент доказал: не лечить CSS/Liquid через JS с `!important`.

## Не путать доказательство и гипотезу

`tag.js`, MutationObserver, изображения, CSS, fonts и third-party должны связываться с конкретным trace/network evidence. Само наличие ресурса ещё не доказывает его причинность.

## Не путать network time и CPU time

`common.v2.27.9.js` может находиться десятки секунд в передаче при плохой сети, не выполняясь десятки секунд на CPU.

## Не смешивать PageSpeed runs

Desktop и mobile, разные throttling conditions и разные запуски нельзя объединять в один «до/после» показатель без явной маркировки.

## Audit discipline

Правильный цикл: **доказательство → маленькая группа изменений → повторный тест → diff → runtime QA**.

# 5. PAGE SPEED FINDINGS, КОТОРЫЕ ДОЛЖНЫ УЧИТЫВАТЬСЯ В КОДЕ

1. **Images:** responsive sizing, modern format, correct dimensions, lazy only for non-critical content.
2. **LCP discovery:** LCP element must be discoverable early; don't add priority only after DOMContentLoaded.
3. **Render-blocking requests:** identify true critical dependencies before deferring.
4. **Unused JS:** inventory third-party/system bundles before removal.
5. **Critical request chain:** reduce unnecessary dependency depth.
6. **Fonts:** controlled loading, limited weights, `font-display: swap/optional` where compatible.
7. **Preconnect:** keep only high-value origins; current reports flag unused Yandex-related preconnects.
8. **Image dimensions:** explicitly reserve geometry where dimensions are known.
9. **DOM:** 778 elements / depth 14 in latest mobile; review but do not mass-refactor solely for this number.
10. **Forced layout:** investigate common.js / Metrica layout sources only with trace correlation.
11. **Security:** CSP/HSTS/COOP/Trusted Types are hardening tasks, not blind edits.
12. **SEO:** keep title, description, canonical, robots, crawlable links, alt and structured data intact.
13. **Agentic:** preserve Agentic Browsing 3/3 and llms.txt compliance.

# 6. FORENSIC RAW TRACE — ОСНОВНОЙ ВЫВОД

Raw trace contains ≈216 661 events.

LCP candidate:

- nodeId **66**;
- nodeName **H1**;
- type **text**;

FCP and LCP occur together at ≈**43,916 с** in the anomalous trace.

`common.v2.27.9.js`:

- request start ≈**2,948 с**;
- priority **Medium**;
- `renderBlocking: in_body_parser_blocking`;
- initiator: HTML parser, line **5659**;
- total ≈**40,78 с**;
- Waiting ≈**2,38 с**;
- Content Download ≈**38,40 с**;
- compressed size ≈**164,5 KiB**.

HTML parser resumes around ≈43,756 s on the region beginning at line 5659. This strongly connects the long network delivery with parser blocking.

### Correct interpretation

`common.js` **does not execute for 40 seconds**. Its network/streaming delivery lasts about 40 seconds in the anomalous trace. Actual main-thread execution is measured in tens of milliseconds.

The `v8.parseOnBackground` interval around 37,6 s must not be interpreted as 37,6 s of CPU blocking.

# 7. WHY THE TWO IMAGES MATTER

The two large images total roughly **5,1–5,2 MiB** and dominated the original payload.

The controlled removal experiment caused a large improvement in both mobile and desktop PageSpeed runs.

Therefore:

**PROVEN:** the two images are a major performance burden and materially contribute to network contention/payload.

**NOT PROVEN:** that they are the only cause of the mobile LCP or the only reason `common.js` receives limited bandwidth.

**PROVEN IN THE RAW TRACE:** LCP itself was a text H1, not the hero image.

Thus the correct model is:

`heavy images → network contention → slower critical resources → parser-blocking common.js becomes extremely expensive → delayed DOM/contentful paint`.
