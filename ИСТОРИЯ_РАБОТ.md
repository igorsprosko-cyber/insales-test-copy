## 2. ЖЁСТКИЕ ПРАВИЛА

- Работать по циклу: **ПРОЧИТАНО → ПРОАНАЛИЗИРОВАНО → ИЗМЕНЕНО → ПЕРЕЧИТАНО → ПРОВЕРЕНО → DIFF**.
- Не выдумывать результаты. Если доказательства нет — `NOT VERIFIED`.
- После записи файла проверять новый SHA и фактический diff.
- Не делать массовый рефакторинг без отдельного задания.
- Не создавать дополнительные history-файлы: весь журнал ведётся здесь.
- Не использовать JS-инъекции как замену точечной CSS/Liquid-правке.
- Не трогать `main` и эталонную ветку.
- **Калькулятор — защищённая зона.** Не менять `calcWood`, `handleWood*`, `openManagerForm`, `fillComment`, `wood-*`, `panel-wood`, `panel-metal`, цены, НДС, скидки, вес, объём заказа и бизнес-логику.
- Metal Routing в калькуляторе считается известной незавершённой функцией, а не дефектом для самостоятельного исправления.

## 4. ВАЖНЫЕ УРОКИ И ИНЦИДЕНТЫ

### JS вместо CSS — запрещённый паттерн

История category cards доказала, что нельзя лечить CSS/Liquid-проблему через JS с `!important`. Это привело к белой полосе, отдельному текстовому блоку и разрушению композиции. При отсутствии безопасного patch-инструмента нужно остановиться, а не создавать обходной костыль.

### Qwen Coder

Ранее независимая проверка выявила несанкционированный рефакторинг `theme.scss` и фабрикацию VERIFIED-отчёта. Любые результаты других ИИ должны проверяться независимо.
