# 5. НЕЗАВИСИМАЯ НАХОДКА P0/P1 — FETCHPRIORITY

В текущем `product.liquid` `fetchpriority="high"` и `loading="eager"` добавляются через `DOMContentLoaded` после поиска изображения.

Это **не эквивалент** server-rendered priority в исходном HTML. К моменту DOMContentLoaded запрос изображения уже мог начаться с обычным приоритетом.

### Решение

Найти фактический `<img>`, создаваемый InSales widget. Если архитектура позволяет — задать `loading="eager"` и `fetchpriority="high"` в исходном HTML/Liquid/widget path. Не добавлять ещё один JS workaround.

# 10. НЕЗАВИСИМАЯ НАХОДКА P1/P2 — H1 → H2 POST-LOAD SCRIPT

В `layouts.layout.liquid` есть `DOMContentLoaded` script, который собирает все H1 и превращает каждый H1 после первого в H2.

### Почему это плохо

- семантика меняется после загрузки;
- добавляется main-thread работа;
- могут затрагиваться H1 системных widgets;
- усложняется accessibility/DOM state;
- это маскирует источник неправильной heading hierarchy.

### Решение

Не удалять сейчас. Сначала inventory H1 по каждому шаблону, затем исправлять Liquid/widget source.

# 16. PRODUCT SCHEMA — P1

Текущий `product.liquid` использует Product + AggregateOffer, low/high price, offerCount, availability, seller и additionalProperty.

Google продолжает отдельно развивать Merchant Listings/Product structured data; актуальную реализацию нужно сверять с текущей документацией, а не считать SEO=100 доказательством merchant eligibility. citeturn1search5

# 26. ФИНАЛЬНЫЙ ВЫВОД

**Да, теперь аудит действительно независимый и комплексный.** Предыдущая версия в основном сверяла предоставленные пользователем PageSpeed reports. Эта версия дополнительно повторно проверила текущий GitHub source и стандарты.

Самая важная новая информация, которой не было достаточно в одном PageSpeed report:

1. Hero priority выставляется слишком поздно через `DOMContentLoaded`.
2. H1 hierarchy исправляется post-load JS вместо корректного HTML/Liquid.
3. OG dimensions жёстко 1200×360 для разных изображений.
4. Google Fonts импортируются page-local многократно.
5. `theme.js` держит body-wide MutationObserver и глобальный capture listener.
6. Product schema содержит вручную заданный minimum order, который расходится с публичным content.

Главный performance порядок остаётся неизменным, но теперь он подтверждён двумя независимыми слоями:

**LCP image → image payload → discovery/priority → mobile JS → third-party → layout → accessibility → schema/data → trust/legal → architecture.**

**Код сайта в этой аудиторской ревизии не изменялся.**
